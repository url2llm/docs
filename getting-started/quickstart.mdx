Make your first url2llm request with cURL or a direct HTTP call from Node.js or Python. Start with one public page, then choose the outputs your application needs.

## 1. Create an account and get your key

[Create an account](https://url2llm.com/sign-up) and open the dashboard. Your first organization is created automatically with 1,000 monthly Free credits. The dashboard creates a default API key when you have no keys.

Copy the secret from the key dialog. If you missed it, open [API keys](https://url2llm.com/dashboard/keys) and reveal or copy an active key. Owners and admins can also choose **Create key** for another application. See [API keys](/account/api-keys) for setup recovery, rotation, and revocation.

Set the secret in the shell where you run the example:

```bash
export URL2LLM_API_KEY='YOUR_API_KEY'
```

Keep the secret in server-side configuration. [API keys](/account/api-keys) covers scopes, live and test prefixes, rotation, and revocation.

## 2. Save an operation key

Generate a unique operation key once, before the request:

```bash
export URL2LLM_OPERATION_KEY="$(uuidgen)"
```

Save the value with your task. Keep it when rerunning an example after a lost response. Do not rerun the generation command for a retry. If `uuidgen` is unavailable, set your own unique value. A different request needs a new value.

## 3. Choose your client

The Node.js example uses built-in `fetch`; the Python example uses the standard library. No url2llm SDK installation is required for these examples.

| Client | Save as | Run |
| --- | --- | --- |
| cURL | No file needed | Paste the command into your terminal |
| Node.js 18 or newer | `example.mjs` | `node example.mjs` |
| Python 3 | `example.py` | `python3 example.py` |

Run the saved example from the same shell where you set `URL2LLM_API_KEY`.

## 4. Send a scrape

This request fetches `example.com` and asks for Markdown and links. JavaScript rendering and main-content extraction are enabled by default.

<CodeGroup>

```bash cURL
curl https://api.url2llm.com/v1/scrape \
  -H "Authorization: Bearer $URL2LLM_API_KEY" \
  -H 'Content-Type: application/json' \
  -H "Idempotency-Key: ${URL2LLM_OPERATION_KEY:?Set URL2LLM_OPERATION_KEY first}" \
  -d '{"url":"https://example.com","formats":["markdown","links"]}'
```

```javascript Node.js
const operationKey = process.env.URL2LLM_OPERATION_KEY
if (!operationKey) throw new Error('Set URL2LLM_OPERATION_KEY to the saved operation key')
const apiKey = process.env.URL2LLM_API_KEY
if (!apiKey) throw new Error('Set URL2LLM_API_KEY before running this example')

const response = await fetch('https://api.url2llm.com/v1/scrape', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${apiKey}`,
    'Content-Type': 'application/json',
    'Idempotency-Key': operationKey,
  },
  body: JSON.stringify({
    url: 'https://example.com',
    formats: ['markdown', 'links'],
  }),
})
const result = await response.json()
if (!response.ok || !result.success) {
  throw new Error(`${response.status}: ${result.error?.message ?? 'Scrape failed'}`)
}
console.log(result.data.markdown)
console.log(result.data.metadata)
```

```python Python
import json
import os
from urllib.error import HTTPError
from urllib.request import Request, urlopen

operation_key = os.environ['URL2LLM_OPERATION_KEY']
if not operation_key:
    raise ValueError('Set URL2LLM_OPERATION_KEY to the saved operation key')
request = Request(
    'https://api.url2llm.com/v1/scrape',
    data=json.dumps({
        'url': 'https://example.com',
        'formats': ['markdown', 'links'],
    }).encode(),
    headers={
        'Authorization': f'Bearer {os.environ["URL2LLM_API_KEY"]}',
        'Content-Type': 'application/json',
        'Idempotency-Key': operation_key,
    },
    method='POST',
)
try:
    with urlopen(request, timeout=45) as response:
        result = json.load(response)
except HTTPError as error:
    result = json.load(error)
    message = (result.get("error") or {}).get("message", "Scrape failed")
    raise RuntimeError(f'{error.code}: {message}') from error

if not result.get('success'):
    raise RuntimeError(result.get('error', {}).get('message', 'Scrape failed'))
print(result['data']['markdown'])
print(result['data']['metadata'])
```

</CodeGroup>

These examples use the operation key you saved in step 2. For an identical retry, keep the same operation key, API key, and body. See [retries](/guides/retries) for a bounded retry loop.

## 5. Check the result

cURL prints the complete JSON response; the Node.js and Python examples print its Markdown and metadata. A successful response contains `success: true` and the page under `data`. This is an illustrative excerpt:

```json
{
  "success": true,
  "data": {
    "metadata": {
      "source_url": "https://example.com/",
      "final_url": "https://example.com/",
      "status_code": 200,
      "credits_used": 1
    },
    "markdown": "# Example Domain",
    "links": [],
    "screenshot": null
  },
  "request_id": "..."
}
```

Check the API's HTTP status and `success` before reading `data`. Then inspect `metadata.status_code` and a known heading or paragraph. The source status is separate from the API's HTTP status. A source `404` can return a page result and is charged.

Requested outputs appear in `data`; outputs you did not request are `null`. Page text and links depend on the source. A scrape either returns all requested outputs or an error.

Each new scrape fetches fresh content. A request that is charged costs one credit. Supported extra formats have no current surcharge. Keep the top-level `request_id` for diagnosis and the source metadata beside content you store.

## Try another operation

| Task | Request | Guide |
| --- | --- | --- |
| Check scrape cost | `POST /v1/quote` with the same scrape body | [Quote and credits](/guides/quote) |
| Search web sources | `POST /v1/search` with `query` | [Search](/features/search) |
| Collect multiple pages | `POST /v1/batch/scrape` or `POST /v1/crawl` | [Collections](/features/collections) |
| Collect domain branding | `POST /v1/brand` with `domain` | [Domain branding](/features/brand-api) |
| Discover site URLs | `POST /v1/map` with `url` and a desired `limit` | [Map API](/features/map) |
| Capture a page image | Enable `screenshot` in the scrape formats | [Screenshots](/features/screenshots) |
| Extract visual identity | Enable `branding` in the scrape formats | [Branding](/features/branding) |
| Return HTML or media references | Select the relevant scrape formats | [Formats](/features/formats) |

Map and search require the `map` key scope. Scrape, quote, crawl, batch, and domain branding use `scrape`. Map returns candidates; use batch for a selected list or crawl to discover and collect pages. Map itself does not launch a collection.

## If the request fails

| Status | Next step |
| --- | --- |
| `401` | Check that the key is set, valid, and not revoked |
| `403` | Check the required key scope or organization permission |
| `402` | Check the shared available credit balance in Billing |
| `400` or `422` | Read the error code and correct the request |
| `429` | Reduce request volume and retry with bounded backoff |
| `503` or `504` | Inspect the transient failure or timeout and use a bounded retry policy |

For production retries, generate an `Idempotency-Key` once per distinct operation and reuse it with identical inputs. See [retries and idempotency](/guides/retries) before retrying a request whose result you did not receive.

---
title: Authentication
description: Authenticate API calls with an organization key.
---

Send an organization API key in the request's authorization header:

```http
Authorization: Bearer YOUR_API_KEY
```

Use this header for scrape, map, search, quote, crawl, batch, domain branding, and collection reads and cancellation. [Create a key](/account/api-keys) before following the [quickstart](/getting-started/quickstart).

## Scopes

| Scope | Operations |
| --- | --- |
| `scrape` | Scrape, quote, crawl, batch, domain branding, and their collection reads and cancellation |
| `map` | Map and web search |

Dashboard-created keys have both scopes. A key must be valid, active, and not revoked. A missing or invalid key receives `401`; a missing scope receives `403`.

Both Live and Test keys use the organization's shared credits and limits. Signing in to the dashboard does not replace the API key required by product endpoints.

## Keep credentials secure

Store keys in server-side configuration or a secret manager. Keep them out of public repositories, browser bundles, URLs, and logs. Rotate or revoke them through [API keys](/account/api-keys).

Your url2llm key belongs in the API request header. The scrape body's `headers` object is sent to the target site; never put your url2llm key there.

## Troubleshoot access

Check the key's scopes, revocation state, and owning organization. Product requests always use the key's organization, regardless of the workspace selected in your browser. See [errors and limits](/guides/errors) for status codes and retry guidance.

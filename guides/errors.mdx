---
title: "Errors and limits"
description: "Handle API errors and rate limits."
---

Errors use the same JSON response structure. Check the HTTP status and `error.code`; keep `request_id` when contacting support.

```json
{
  "success": false,
  "error": {
    "code": "AUTHENTICATION_ERROR",
    "message": "Authentication required",
    "details": null
  },
  "request_id": "..."
}
```

Use the returned `error.code` and message from the actual response.

## Check the HTTP status

| Status | Meaning |
| --- | --- |
| `400` or `422` | Invalid request or unsupported format. |
| `401` | Missing or invalid authentication. |
| `402` | Insufficient credits. |
| `403` | Missing key scope or permission. |
| `404` | Requested resource not found. |
| `409` | Conflicting request state. |
| `429` | Rate limit reached. |
| `500`, `503`, `504` | Server error, temporary service failure, or timeout. |

Handle `429` and transient `5xx` responses with bounded retries and backoff. Reuse the same `Idempotency-Key` when retrying identical product inputs, including collection creation. Use a new key for each distinct request. See [retries and idempotency](/guides/retries) for replay and conflict behavior.

## Stay within rate limits

| Operation | Limit | Shared scope |
| --- | --- | --- |
| Scrape | 120/minute | Organization |
| Map, search, and collection creation | 30/minute combined | Organization |
| Quote | 240/minute | Organization |
| Collection and account reads, and collection cancellation | 300/minute combined | Organization |

The Playground shares these limits with API clients. The 300/minute limit includes account reads for usage, activity, billing, and API key lists. Current limits are not plan-specific, and extra API keys do not multiply them. Respect `Retry-After` when supplied. Crawl and batch accept at most 100 pages; at most ten collections can be active per organization. Limits can change as service capacity changes.

## Check the error code

| Code | Status | What to check |
| --- | --- | --- |
| `AUTHENTICATION_ERROR` | `401` | Credential validity and revocation |
| `PERMISSION_DENIED` | `403` | Required key scope |
| `INSUFFICIENT_CREDITS` | `402` | Available organization balance |
| `RATE_LIMIT_EXCEEDED` | `429` | Shared request volume and bounded backoff |
| `IDEMPOTENCY_KEY_ALREADY_ACCEPTED` | `409` | An accepted request whose replay is unavailable |
| `IDEMPOTENCY_KEY_CONFLICT` | `422` | Reusing an operation key with changed inputs |
| `UPSTREAM_TIMEOUT` | `504` | Request deadline and source response |
| `SERVICE_UNAVAILABLE` | `503` | Temporary source or service availability |

Use the code actually returned by the API. A scrape can return source metadata for a fetched page; that source status is separate from the API response's HTTP status. A source `404` can be charged and recorded as an error in usage even when the API returns page content.

Limits are shared across the organization's API keys. Creating more keys does not multiply the organization allowance.

## Contact support

Keep the top-level `request_id`, endpoint, target URL, request time, and organization ID. Include the error code and message, but omit API key secrets and target-site credentials. [Activity](/account/usage#understand-activity) can show whether credits were charged or released.

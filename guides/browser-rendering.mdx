---
title: Browser rendering
description: Control JavaScript, mobile profiles, location, and capture timing.
---

JavaScript rendering is enabled by default for a scrape. Use it when a public page fills its content after navigation or when requesting screenshots, branding, or assets.

## Turn JavaScript on or off

For a page whose useful content is already in HTML, a text-only request can disable JavaScript:

```json
{
  "url": "https://example.com",
  "formats": ["markdown", "links"],
  "renderJs": false
}
```

`renderJs: false` cannot be combined with screenshots, branding, assets, or a nonzero `waitFor`. A browser does not guarantee access to a source that blocks the request, and changing an output format does not resolve a stable source block.

## Choose mobile, country, and language settings

```json
{
  "url": "https://example.com",
  "formats": ["markdown", "screenshot"],
  "mobile": true,
  "location": { "country": "US", "languages": ["en-US"] },
  "blockAds": true
}
```

`mobile` requests a mobile browser profile. `location` requests a country and language preference. A site may ignore these preferences or return untranslated content.

Ad blocking is enabled by default. Set `blockAds: false` when the ad requests are relevant to the page state you want to capture. Mobile profiles are separate from custom viewport dimensions, which are not exposed by the API.

## Wait after navigation

`waitFor` adds a delay in milliseconds after load. The request must leave time for navigation and capture:

```json
{
  "url": "https://example.com",
  "formats": ["markdown", "screenshot"],
  "waitFor": 1000,
  "timeout": 30000
}
```

Requests require `timeout` to be greater than `waitFor + 3000`. A larger wait does not guarantee that the page has completed every background request. Test a known heading, image, or other value to check on your source.

`timeout` bounds the complete request. Use a bounded retry policy for a transient timeout. See [retries](/guides/retries).

## Send headers to the target site

```json
{
  "url": "https://example.com",
  "formats": ["markdown"],
  "headers": { "Accept-Language": "en-US" }
}
```

The request body's `headers` are sent to the target site. Your url2llm bearer key belongs in the API request's `Authorization` header, never in this object. Only send target credentials to a source you trust.

The API does not expose click, scroll, selector-wait, named browser profile, or persistent cookie-session workflows.

---
title: API keys
description: Get, use, rotate, and revoke your API keys.
---

Every product API request needs an API key. Manage keys in [Dashboard > API keys](https://url2llm.com/dashboard/keys). Only organization owners and admins can create, reveal, or revoke them.

## Get your first key

1. [Create an account](https://url2llm.com/sign-up) and open the dashboard.
2. Your first organization is created automatically with 1,000 monthly Free credits. The dashboard sets up a default key when you have no keys.
3. Copy the secret from the key dialog and save it in your application's secret manager.

If you close the dialog or the secret could not be received, open **API keys** and use the eye or copy button beside an active key. Some older keys cannot be revealed; create a replacement if needed.

If setup fails before a key is created, retry setup or choose **Create key**. Members who cannot manage keys should ask an organization owner or admin for access.

## Create another key

1. Open [API keys](https://url2llm.com/dashboard/keys) and choose **Create key**.
2. Enter a name that identifies the application using it.
3. Leave **Live key** on for a Live key, or turn it off for a Test key.
4. Choose **Create key**, then copy and save the secret.

Use separate keys for separate services so you can revoke one without replacing every application's key.

## Use your key

Set the key in your server or local shell:

```bash
export URL2LLM_API_KEY='YOUR_API_KEY'
```

Send it on every product request:

```http
Authorization: Bearer YOUR_API_KEY
```

Requests use the key's organization, regardless of the organization selected in your browser. All keys in that organization share its credits and rate limits.

Keep the secret out of source control, browser code, URLs, and logs. The scrape body's `headers` object is sent to the target site; never put your url2llm key there.

## Check scopes and key mode

| Scope | Operations |
| --- | --- |
| `scrape` | Scrape, quote, crawl, batch, domain branding, and collection reads and cancellation |
| `map` | Map and web search |

Dashboard-created keys include both scopes. A valid key without the required scope receives `403`.

Live keys start with `u2l_live_`; Test keys start with `u2l_test_`. Both use the same credits and limits. Test mode does not make requests free or create a payment sandbox.

## Rotate a key

1. Create a replacement key and update the applications using it.
2. Verify a request with the replacement.
3. Finish or cancel collections started with the old key. Resolve uncertain requests with the original key and [idempotency key](/guides/retries).
4. Revoke the old key.

If a key is compromised, revoke it immediately. Do not wait to finish routine rotation.

## Revoke a key

1. Open [API keys](https://url2llm.com/dashboard/keys) and find the key by name or prefix.
2. Choose **Revoke**, then confirm with **Revoke key**.
3. Select the **Revoked** filter to see the key and its usage history.

Revocation cannot be undone. New requests using the key receive `401`, and its secret can no longer be revealed. Pending collections started with the key stop. Completed work keeps its charges and history.

A replacement key cannot replay an operation accepted with the revoked key. For an uncertain earlier request, check [Activity](/account/usage) or contact [support](mailto:support@url2llm.com) before starting a new operation.

## Check usage or access errors

The API keys page shows requests, credits used, and last use for each key. Use [Activity](/account/usage) to inspect individual requests.

For `401`, check the secret and revocation state. For `403`, check the required scope. For `402`, check the organization's available credits in [Billing](https://url2llm.com/dashboard/settings/billing).

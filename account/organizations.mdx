---
title: Organizations
description: Understand workspace ownership and switch between organizations.
---

An organization owns its API keys, credits, billing, and usage history. Your personal account can belong to more than one organization, but the dashboard shows one active organization at a time.

## Your first organization

Signup automatically provisions your first organization. Start from the [dashboard](https://url2llm.com/dashboard); no separate organization-creation step is needed. Invite teammates through [team access](/account/team-access).

## Switch organizations

Use the organization switcher in the dashboard header to select an organization you already belong to. The dashboard returns to Overview and loads that organization's keys, credit balance, and usage.

Check the active organization before creating keys, inviting members, changing billing, or troubleshooting a balance. Switching the dashboard does not change the owner of an API key already deployed in your application. Product requests always use the organization that owns the key.

## Update the organization profile

Open [Settings > Organization](https://url2llm.com/dashboard/settings/organization). Authorized users can choose **Update organization** to change its name and logo. If a slug is shown, the editor accepts lowercase letters, numbers, and hyphens.

The page also displays the organization ID with a copy control. Use that ID to distinguish similarly named workspaces when contacting support. Changing the display name or logo does not move credits or keys between organizations.

## Shared resources

| Resource | Ownership |
| --- | --- |
| API key | One organization, with its own scopes and usage attribution |
| Available credits | Shared by every key in that organization |
| Subscription and prepaid credits | The organization that purchased them |
| Member role | That person's membership in that organization |
| Password, profile, and connected sign-in accounts | The personal account |

Administrative access in one organization does not grant administrative access in another. See [team roles](/account/team-access#roles-and-permissions) for capabilities and [billing](/account/billing) for shared credit periods.

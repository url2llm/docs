# url2llm docs

Customer API-access guides and reference. `openapi-public.json` is generated by the backend. Architecture, deployment, and the internal proposed contract stay in `backend-core/docs/`.

## Local preview

Use Node.js 22 or newer:

```sh
npm ci
npm run check
npm run dev
```

Preview at `http://localhost:3002`. The request playground stays disabled until its service URL and authentication setup are configured.

## Update the implemented API

The checked-in snapshot pins the reference to a reviewed backend contract. Never edit `openapi-public.json` directly. Export locally from `backend-core/` when changing the API:

```sh
uv run --locked python scripts/export_openapi.py --output ../webapp/api/openapi.json --public-output ../docs/openapi-public.json
```

The backend keeps no duplicate snapshots. Run `npm run check` here and regenerate the Orval client in the webapp. Update both consumers for coordinated releases; deployment workflows do not transfer schemas between repositories.

Review and commit the snapshot with any affected guides. Mintlify generates endpoint pages from it. General explanations and task guides stay handwritten. Mintlify owns the public API-access guides; do not duplicate them in the webapp.

## Guide layout

- `getting-started/`: introduction, quickstart, and API-key authentication.
- `account/`: API keys, credits, prepaid billing, and usage attribution.
- `features/`: scrape, map, search, crawl and batch, domain branding, format selection, text, screenshots, links, assets, and page branding.
- `guides/`: HTTP clients, quote, rendering, retries, and errors.

Keep each topic in its existing guide and link to it from overviews. Update `docs.json` navigation and preserve old public URLs with redirects when moving a page. Parameter schemas stay in OpenAPI; guides explain examples and behavior.

## Public scope

Every guide explains supported API requests, responses, authentication, outputs, limits, retries, credits, or billing. Keep request and response examples beside the operation they demonstrate. Link to the dashboard only when customers need to obtain a key, manage credits, or inspect usage.

Dashboard tutorials and internal account endpoints are outside this reference. The proposed contract is maintained in `../backend-core/docs/openapi-proposed.json` with its existing design guide; it is not a customer API snapshot or a code-generation input.

## Publishing

Connect this Git repository to Mintlify, select its publishing branch, and use `/` as the documentation directory. Mintlify reads `docs.json`. The public documentation domain is `https://docs.url2llm.com`. The webapp links directly to it and permanently redirects its former `/docs` routes to the matching Mintlify pages. Keep those redirects when changing guide paths.

Official references: [OpenAPI setup](https://www.mintlify.com/docs/api-playground/openapi-setup) and [configuration](https://www.mintlify.com/docs/organize/settings).
